# 复盘、分支推演与下一手预测

本地 Web 应用，支持载入比赛、逐步回放选禁、查看每一步的可选英雄及不可选原因，并从任意一步创建分支手动推演。分支单独保存，不改动比赛记录。

第二阶段加入了**下一手预测**和**预测反馈**，模型与评估见[下一手预测](../model/next-action.md)。第三阶段加入了**阵容评估**面板（对线期望、双人组合、阵容画像），见[阵容评估](../model/composition.md)。第四阶段加入了**候选对比**面板，见[候选对比](../model/recommend.md)。

## 运行

前提：已用 `python3 scripts/build_dataset.py` 生成本地 SQLite（`data/processed/lol_bp.sqlite3`）。

```sh
uv venv .venv --python 3.13 && uv pip install --python .venv/bin/python -r requirements/app.txt
(cd web && npm install && npm run build)
.venv/bin/uvicorn lolbp.api:app --host 127.0.0.1 --port 8000   # 打开 http://127.0.0.1:8000
```

日常使用可以直接用仓库根目录的脚本：

```sh
./start.sh                 # 后台启动并打开浏览器；前端源码有改动时会先重新构建
./stop.sh                  # 关闭
PORT=8001 ./start.sh       # 换端口；OPEN=0 不自动打开浏览器
```

PID 和日志在 `data/app/server.pid`、`data/app/server.log`（不入库）。`start.sh` 会检查 `.venv`、本地数据库和端口占用；`stop.sh` 只会结束本应用的 uvicorn 进程。

开发前端时另开 `cd web && npm run dev`，访问 5173 端口，`/api` 会代理到 8000。地址栏 hash 记录当前比赛、步数和分支（如 `#game=LOLTMNT02_463373&step=12`），可以收藏或分享。

预测直接使用仓库里已训练的模型文件（`models/next_action/`），运行应用不需要 numpy；只有训练新版本才需要（见[下一手预测](../model/next-action.md)）。

## 结构

| 位置 | 内容 |
| --- | --- |
| `lolbp/draft.py` | 纯函数状态机：按先选方映射 20 步模板、计算下一步、检查合法性（本局已用、Fearless 已消耗、赛事禁用、未知英雄、空 pick）、回放历史 |
| `lolbp/repository.py` | 只读数据层：比赛、系列赛分组、逐手顺序来源、规则解析、英雄目录 |
| `lolbp/branches.py` | 分支存储于 `data/app/branches.sqlite3`（不入库）：分叉步数、可选的 Fearless 假设、用户动作 |
| `lolbp/api.py` | FastAPI 接口；存在 `web/dist` 时同时提供前端页面 |
| `lolbp/check.py` | `python3 -m lolbp.check`：全量回放，汇总与规则不一致的记录 |
| `lolbp/history.py` | 按日期截断的历史统计：队伍、选手、补丁与全局的时间加权计数 |
| `lolbp/predict.py` | 版本化模型文件、特征、合法候选上的条件 logit 排序与依据说明 |
| `lolbp/backtest.py` | 时间切分、争议局排除、逐手决策迭代与命中率统计（训练和评估脚本共用） |
| `lolbp/composition.py` | 阵容评估：对线 15 分钟经济期望、双人组合残差、Data Dragon 粗粒度画像，按推断分路计算 |
| `lolbp/recommend.py` | 候选对比：为轮到的一方列出候选及职业常见度、选手、对线、阵容变化、对手回应、ban 的对手需求与机会成本 |
| `lolbp/feedback.py` | 预测反馈：保存局面快照、期望名次，并用任意版本重新检查 |
| `models/next_action/` | 模型版本文件、切分设置 `settings.json`、评估报告 `reports/` |
| `scripts/train_next_action.py`、`scripts/evaluate_next_action.py` | 训练（需 numpy）与评估（标准库） |
| `web/` | React + TypeScript + Vite 前端：系列赛浏览、选禁面板、时间线、英雄网格、预测面板、规则与证据面板、分支面板、反馈记录 |

## 数据与规则口径

- **逐手顺序**：优先使用与 OE 最终阵容一致的 Leaguepedia 逐手表；否则把 OE 列按模板排布，界面标明来源及实测一致率 99.83%（见[黄金集](../data/oe-order-golden-set.md)）。Leaguepedia 同队连选两手（8–9、10–11、18–19 步）的组内先后在时间线上另有提示。
- **规则字段**：每项规则带状态，界面直接显示，不把假设当作事实。
  - 选禁模板：有规则书时为"规则书确认"；否则为"实践观察"，依据是 2,376 局逐手表全部符合 20 步蛇形。
  - 跨局限制：有规则书时为"规则书确认"；否则按年份假设，2025 年起为 Fearless，此前为无限制。创建分支时可以改设，记为"用户假设"。
  - 赛事禁用：优先使用规则书名单（目前都未取得）；其次使用 Leaguepedia Data 页的 SetPatch 名单，状态为"Leaguepedia 记录"，会实际拦截；都没有时为"未知"，不拦截。
  - 规则书字段可能是"规则书确认"（observed），也可能是"规则书推断"（inferred，例如 2026 Worlds 和 2025 LCK 的 Fearless 适用）。
- **合法性**：在本局已选或已禁、Fearless 已消耗（仅限制 pick）、赛事禁用、未知英雄、空 pick 这几种情况下阻止操作。禁用已消耗英雄可以执行，但会提示"该 ban 无效"（与 2026 LCK 规则 §7.7.1.2.4 一致）。
- **历史回放**：历史记录按原样显示，不被改写。与规则不一致之处在时间线上标出并列在证据面板中，因为可能是记录错误，也可能是规则假设不成立。
- **系列赛分组**：gameid 带系列号（如 `11896-11896_game_1`）时直接使用；否则把同联赛、同一对队伍、相隔 6 小时内的比赛串成一个系列赛。局序不连续的系列赛会标出，此时 Fearless 前序局可能不全。
- **英雄池**：名称与头像使用 16.20.1 目录（173 名英雄，带中英文名，头像在运行时从 Data Dragon CDN 加载）。每局可选范围按该局补丁对应的 Data Dragon 版本确定（`data/curated/champion_availability.json`，由 `scripts/collect_champion_availability.py` 生成）：当时尚未上线的英雄标为“该补丁尚未上线”并被拦截，预测也不再把它们当作候选。全量回放中没有任何历史动作用到未上线英雄。

## 验收（2026-10-29）

- **全量回放**：5,406 局、2,122 个系列赛（1 个局序异常）。2024 年及以后有 2,375 局使用 Leaguepedia 逐手表，其余使用 OE 列。
  - 与规则不一致的步骤只有 1 处：2024 LPL `10699-10699_game_2` 第 15 步 ban 了本局已用英雄，判断为记录问题，按原样保留。
  - 2025–2026 全部比赛在假设的 Fearless 规则下没有违规 pick。另有 4 次禁用已消耗英雄，符合规则（该 ban 无效）。这说明数据与假设一致，但不等于取得了规则书证据。
- **测试**：状态机 9 项，API 3 项（基于临时数据集，覆盖分组、回放、合法性、分支的创建、推演、撤销、删除，Fearless 假设覆盖，以及历史不被修改）。全仓离线测试共 84 项通过。
- **实际页面**：在本机浏览器检查过历史回放、分支推演，以及 500px 宽度下的布局。

## 下一手预测与反馈（2026-10-29）

- **预测面板**：位于英雄网格上方。回放和分支中都会显示轮到的一方下一手的前 10 个候选、概率、主要依据（点击展开更多），以及数据不足提示和该阶段的验证集命中率。
- **回放与分支的差异**：回放时，实际的那一手会高亮；同队连选时另一手的名次也会列出。分支中可以直接“执行”某个候选。
- **模型切换**：右上角选择模型版本，选择会记在浏览器本地。
- **标记反馈**：见[反馈与回归检查](../model/next-action.md#反馈与回归检查)。右侧“反馈记录”按当前所选版本重新检查每一条，并可跳回当时的局面。
- **界面整理（2026-10-29）**：
  - 下一手预测、候选对比、阵容评估改为标签页，英雄网格固定在下方；上次选的标签页会被记住。
  - 英雄网格的头像上显示模型预测名次（前 10 名）。
  - 回放时可以用 ←/→ 逐步前进或后退。
- **验收**：
  - 离线测试 106 项通过，其中训练测试需要 numpy，在 `.venv` 中跳过。
  - 新增测试覆盖：按日期截断、摇摆位置、合法候选、系列赛 ban 随队伍 ID 跟踪（换边后仍正确）、版本校验、按组计分、争议局识别、反馈期望与结论、反馈存储、预测与反馈接口、牛顿法恢复权重。
  - 用隔离的测试服务和无头 Chrome，在 1440px 和 500px 宽度下检查了回放、分支和反馈面板。
- **附带修复**：分支存储此前每次请求都留下未关闭的 SQLite 连接（`with sqlite3.connect()` 只提交不关闭），现在会显式关闭。
