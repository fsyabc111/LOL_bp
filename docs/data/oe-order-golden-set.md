# OE 选禁顺序准确率（Leaguepedia 黄金集）

测量日期：2026-10-29。结论：在 2024–2026 年 LCK、LPL、Worlds 可对照的 2,375 局中，OE 每队 pick1–5、ban1–5 按 20 步蛇形模板排布后，与 Leaguepedia 逐手表一致的比例为 **99.83%**（同队连选两手的内部顺序不比较）；逐字完全一致的比例为 99.71%。先选方 100% 一致。按设计决定，OE 列可作为**已测误差的逐手顺序来源**用于统计和建模；正式复盘仍优先使用逐局核验过的序列。

```sh
python3 scripts/collect_leaguepedia_pb.py            # 联网；已缓存的页面直接复用
python3 scripts/collect_leaguepedia_pb.py --offline  # 只用本地原始缓存重建
python3 scripts/measure_oe_order.py                  # 输出 data/curated/oe-order-accuracy.json
```

## 来源与采集

数据来自 Leaguepedia 各赛段的 Picks and Bans 页面，共 32 页：2024 LCK 夏季季后赛，以及 2025–2026 年 LCK、LPL 全部赛段和 Worlds 入围赛、正赛。采集通过公开 MediaWiki `action=parse` 接口渲染页面：

- 逐页顺序请求，间隔 8 秒；遇到 `ratelimited` 时有限退避，最多尝试 3 次。
- 不使用 Cargo。匿名访问 Cargo 当日返回 ratelimited，原始 wiki 文本（`action=raw`）返回 403。
- 原始 JSON 按 SHA-256 存在 `data/raw/leaguepedia-pb/`（不入库）。`data/manifests/leaguepedia-pb.json` 记录页面标题、修订号、URL、获取时间、字节数、哈希和每次尝试的结果。

表头 `T1B1 T2B1 … T1P1 T2P1-2 T1P2-3 … T2P5` 即 20 步全局顺序，Team1 为先选方，每个单元格标明红蓝方。几点处理约定：

- 空 ban 在表中渲染为名为 "None" 的占位图标，记为 null。
- 同一单元格里的两手（第 8–9、10–11、18–19 步）是同队连选，表格不保证其内部先后，比较时按组处理。

**与 OE 的关联**：要求红蓝双方最终 pick 集合唯一匹配一局 OE 比赛，不按队名模糊匹配。2,378 行中 2,376 行唯一关联，2 行在 OE 中找不到对应比赛，没有歧义。关联结果写入 `data/curated/bp_sequences.jsonl`，每行带页面修订号与表格行定位。内容沿用 Leaguepedia 的 CC BY-SA 3.0 署名（见 [SOURCES.md](../../data/SOURCES.md)）。

"证据被拒"指 Leaguepedia 序列本身与 OE 最终集合不一致，不参与顺序对照。2026 LPL 的 `13429-13429_game_2` 中，蓝方 5 个 ban 有 3 个两源不同；哪一方正确未判定。

全部 2,376 局 Leaguepedia 序列均符合 20 步蛇形模板（行动方与 ban/pick 类型逐步一致）。这是"实际比赛按此顺序进行"的观察证据，**不等于**取得了 2025–2026 LPL 与 Worlds 的规则书条款，所以 `rules.json` 中这两项赛事的模板仍为 unknown。

## 证据边界

- **独立性**：Leaguepedia 由社区人工录入，OE 来自赛事数据源，两者可能有部分共同上游（例如官方转播数据）。4 局顺序差异和 1 局 ban 差异说明两者并非简单复制，但 99.8% 的一致率仍不能等同于两次独立的录像核验。建议对上表 5 局以及少量随机局做录像抽查。
- **覆盖面**：只覆盖已抓取的赛段。OE 中标为 LCK/LPL 的部分比赛不在这些页面里（例如 2025 LCK 的 OE 记录多于关联局数），未覆盖的局没有测量值。
- **适用范围**：本测量只说明逐手顺序。规则合法性（Fearless 范围、赛事禁用名单）仍需规则证据。Data 页中的 `SetPatch` 记录了赛事禁用英雄（例如 2024 LCK 夏季季后赛禁用 Aurora），这条线索可在补规则时一并采集。
