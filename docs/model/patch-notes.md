# 第五阶段（一）：补丁说明信号

更新日期：2026-10-29。状态：数据已采集，并作为下一手预测的特征做了两次实验（v3、v4），在验证集上都没有改善，默认模型仍为 v1。

## 数据

`scripts/collect_leaguepedia_patches.py` 读取 Leaguepedia 2025–2026 年全部 46 个补丁页面（25.S1.1 至 26.21），包括联赛跳过的补丁。读取方式与其他 Leaguepedia 采集相同：顺序请求，间隔 7 秒，原始响应按哈希存放在 `data/raw/leaguepedia-patches/`，清单在 `data/manifests/leaguepedia-patches.json`。

共得到 708 条英雄改动，写入 `data/curated/patch_changes.jsonl`。每条记录包括：日期、英雄、设计师说明（截取前 600 字）、改动行数、方向（加强 343 / 削弱 306 / 调整 59），以及判定方向用的两类投票：

- **说明关键词**：例如 "too strong"、"overperforming" 计为削弱，"underperforming"、"struggling" 计为加强。这一项权重加倍。
- **数值方向**："旧值 ⇒ 新值"的变化方向。冷却、消耗、施法时间这类数值，变小算加强。

两类投票方向一致时，标为加强或削弱；不一致时标为调整。406 条主要依据说明关键词，259 条依据数值，43 条两者都没有信号。

抽查 12 条，11 条与设计师说明一致；卡蜜尔那条"削弱辅助、保留其他位置"的混合改动被判成了加强。整体可以当作准确率约 85–90% 的噪声标签。

内容沿用 Leaguepedia 的 CC BY-SA 3.0 授权。

### 补丁号对照（解决了 P0 的遗留问题）

OE 的补丁号与 Leaguepedia 的补丁名，按同一局比赛逐局比对（证据来自 `event_restrictions.jsonl` 中 Leaguepedia 赛事页面记录的补丁号），在 2025–2026 年的 2,680 局里一一对应，没有冲突：

- 15.01–15.03 对应 25.S1.1–25.S1.3
- 其余 15.xx 对应 25.xx
- 16.xx 对应 26.xx

对照表写在 `data/curated/patch_mapping.json`。出现任何冲突，采集脚本都会直接失败。这是社区记录层面的逐局证据，不包括热修复，也不证明赛事服务器的实际部署版本。

## 特征与实验

**"新近改动"的定义**：取本局之前职业比赛用过的上一个补丁，从它之后到本局补丁为止，所有补丁页面里的改动都算，所以联赛跳过的补丁也算在内。日期晚于本局的改动块（补丁中途的更新）不算。

特征强度按 20/(20+本补丁已有局数) 衰减。新补丁刚出时，主要依靠补丁说明；本补丁局数多了以后，交给实际统计。

| 版本 | 新增特征 | 验证集 Top-1 / Top-5 | 本补丁前 10 局 Top-1 / Top-5 |
| --- | --- | --- | --- |
| v1 | — | 21.1% / 62.1% | 18.5% / 54.6% |
| v3 | 被加强、被削弱 | 21.1% / 62.1% | 18.7% / 54.2% |
| v4 | v3 + 说明里提到职业赛场 | 21.1% / 62.2% | 18.8% / 54.4% |

两版都没有改善，差异在噪声范围内。

拟合出的权重显示：前两个阶段里，"被加强"和"被削弱"的权重**都是正的**（0.3–0.6）。被改动的英雄更容易被选或被禁，但加强还是削弱几乎无关。设计师削弱的往往是本来就太强的英雄，削完通常还是热门。

## 新补丁初期预测偏弱，主要原因不在补丁本身

把验证集按"本补丁此前局数"和"两队距离上一场比赛的间隔"交叉分组，看 v1 的 Top-5：

| | 常规赛程 | 刚经历 14 天以上休赛 |
| --- | ---: | ---: |
| 本补丁前 10 局 | 59.0%（1,160 手） | 46.3%（620 手） |
| 本补丁 10 局以后 | 64.3%（7,859 手） | 57.4%（800 手） |

休赛之后的影响（约 7–13 个百分点）比补丁新旧的影响（约 5–7 个百分点）更大。新赛段开始、阵容变动、国际赛之后，队伍和选手的习惯会变化，而统计仍然主要来自休赛前的比赛。

职业比赛通常在补丁发布约一周后才开始用新版本。到那时，各队训练赛已经把版本强弱试出来了，开局几场职业比赛本身就已经反映了这些信息，补丁说明提供不了更多。

## 下一步方向

- **处理休赛期之后的变化**（优先）：例如休赛后让近期数据或新阵容的权重更高；或者识别选手转会和位置变化，休赛后的前几场更依赖选手个人历史，而不是队伍历史。
- **韩服排位信号**：可以反映新补丁和休赛期间英雄强度的实际变化。需要 Riot API Key。
