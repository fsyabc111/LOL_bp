# 第三阶段：阵容评估（c1）

更新日期：2026-10-29。状态：第一版已接入应用，并在训练集与验证集上回测；保留测试集尚未使用。

对任意一步的 BP（历史回放或分支，未完成的也可以）给出三类证据，分开呈现：

- **对线期望**：每个位置双方英雄交手时，15 分钟经济差的期望值，并附样本量。
- **双人组合**：下路+辅助、中单+打野、上单+打野这几组，同队时的胜率和经济，比"两个英雄各自的水平"高还是低。
- **阵容画像**：魔法/物理伤害比例、前排数量、远程数量。

结论先说：对线期望能部分反映对线结果，但第一版的任何信号都**不能预测胜负**。所以界面上把它们当作带样本量的描述，不当作胜负判断。

## 回测结果

切分沿用[下一手预测](next-action.md)的 `settings.json`：训练集 2025-01 至 2026-03，验证集 2026-04 至 07。收缩强度和半衰期只在训练集上选，验证集只用来确认。

| | 训练集 | 验证集 |
| --- | --- | --- |
| 有 15 分钟数据的对线（个） | 4,620 | 2,525 |
| 平均绝对误差：恒为 0 | 527 | 619 |
| 平均绝对误差：英雄位置均值 | 519 | 601 |
| 平均绝对误差：均值 + 直接交手修正 | 519 | 601 |
| 与实际经济差的相关系数 r | 0.19 | 0.22 |
| 前期期望区分胜负的 AUC | 0.54 | 0.48 |
| 双人组合残差区分胜负的 AUC | 0.49 | 0.48 |
| 参照：实际 15 分钟经济差区分胜负的 AUC | 0.78 | 0.81 |

怎么理解：
- **对线期望有一点信息，但不多**：误差只降低约 3%，相关系数 0.2 左右。上单最好（验证集 r=0.35），下路最弱（0.11）。
- **直接交手几乎不带来额外信息**：在现有样本量下，对位结果基本能被"两个英雄各自在该位置的平均水平"解释。不同收缩强度之间的差异不到 1 金币。
- **前期期望不能区分胜负**：实际 15 分钟经济差能很好地区分胜负（AUC 0.8），但从阵容推出的期望不能（AUC 约 0.5）。可能的原因是，队伍选前期强势的英雄时，往往以后期为代价。
- **双人组合残差没有预测力**：所以只在列表里描述，不作为结论标黄。

完整数字在 `models/composition/reports/c1.{train,validation}.json`，界面上的回测说明读取验证集报告。

## 方法

- **只用此前日期，按时间加权**：与第二阶段相同，只用该局日期之前的比赛，半衰期 180 天。
- **对线期望 = 英雄位置均值 + 直接交手修正**：
  - 英雄位置均值：该英雄在该位置的平均 15 分钟经济差，向 0 收缩（相当于 20 局的先验）。
  - 直接交手修正：两个英雄直接交手时，实际结果相对于均值之差的平均，再收缩（相当于 50 局的先验）。
  - 视角统一为蓝方。
- **双人组合**：用两个英雄各自的胜率（向 50% 收缩）推出组合的预期胜率，再计算同队时实际胜率比预期高多少。经济部分同理，用两人 15 分钟经济差之和。少于 20 局不下结论。
- **分路推断**：按英雄的历史分路分布取最可能的分配，不使用本局最终分路。最可能分配的概率不到 60% 时，界面会标"分路存疑"。
- **阵容画像**：来自 Data Dragon 的 tags 与 0–10 的攻击、魔法、防御评分。这是 Riot 的粗粒度描述，不是实测伤害构成，也不一定随补丁更新。
  - 由 `scripts/build_champion_traits.py` 从固定的原始缓存生成 `data/curated/champion_traits.json`，生成前会核对原始文件哈希。
  - 3 个以上英雄时，魔法占比低于 25% 或高于 75% 会提示。
  - 4 个以上英雄都没有前排时，会提示。
- **结论阈值**：对线提示要求两边英雄在该位置都有至少 5 局 15 分钟数据，且期望差至少 300 经济。

参数在 `models/composition/settings.json`。

## 数据缺口

- **LPL 缺对线数据**：LPL 在 2026 年之前没有 15 分钟数据，所以只在 LPL 打过的英雄组合，对线期望会标"数据不足"。
- **缺少更细的机制数据**：控制链、开团、位移等更细的阵容信息，需要 CommunityDragon 的技能数据，本机网络不稳定，这一版没有接入。
- **刻意未做发力窗口和资源情景**：直接用"比赛时长对胜率"的统计会受筛选偏差影响（设计文档 6.4），这一版没有做。
