# 第二阶段：预测下一手

更新日期：2026-10-29。状态：v1 已训练并在验证集评估；保留测试集尚未使用。

给定一局比赛停在任意一步（历史回放或分支），对“轮到的一方下一手会选或禁谁”在全部合法英雄上排序，给出概率、依据和数据不足提示。预测的是职业队伍的实际习惯，不是最优选择；概率是“下一手选谁”的估计，不是胜率。

## 结果（验证集）

验证集为 2026-04-01 至 2026-07-31 的 522 局（另排除 4 局逐手顺序有争议的 2026 LPL 比赛），共 10,439 手。两条基线：“版本热门”（ban 看本补丁 ban 率，pick 看己方空缺位置的本补丁热度）；“选手常用”（pick 看己方空缺位置选手的近期英雄，ban 看对手空缺位置选手的近期英雄）。

| 版本 | Top-1 | Top-3 | Top-5 | Top-10 | MRR | log loss |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline-meta | 16.4% | 37.2% | 50.2% | 70.3% | 0.326 | 3.201 |
| baseline-player | 11.5% | 27.6% | 38.9% | 58.9% | 0.257 | 3.365 |
| **v1** | **21.1%** | **47.0%** | **62.1%** | **81.1%** | **0.393** | **2.756** |

按阶段（Top-1 / Top-5）：

| 阶段 | baseline-meta | baseline-player | v1 |
| --- | --- | --- | --- |
| 第一轮禁用（1–6 步） | 25.2% / 62.4% | 5.6% / 20.9% | 27.1% / 70.5% |
| 第一轮选择（7–12 步） | 13.5% / 46.3% | 12.2% / 42.4% | 18.5% / 57.2% |
| 第二轮禁用（13–16 步） | 6.5% / 28.7% | 12.6% / 42.4% | 17.5% / 55.8% |
| 第二轮选择（17–20 步） | 17.7% / 59.4% | 18.4% / 56.9% | 19.5% / 62.9% |

v1 在四个阶段都高于两条基线，第二轮禁用提升最大：这一轮主要针对对手还空着的位置和对应选手的英雄池，单看版本热度效果很差。LCK（4,760 手）与 LPL（5,679 手）的 Top-5 分别为 62.4% 和 61.8%，差别很小。

校准：v1 最高候选的概率与实际命中大体一致，只在高把握区间偏自信。最高概率在 0.1–0.2 的 5,938 手平均概率 14.6%，命中 19.4%；0.3–0.5 的 1,085 手为 36.9% 对 33.0%；超过 0.5 的 106 手为 57.3% 对 29.3%。低区间命中偏高，部分来自同队连选按组计分（见下文）。

完整数字在 `models/next_action/reports/<版本>.validation.json`，界面上的“该阶段验证集命中”读取同一份报告。

## 数据与防泄漏

- **只用此前日期**：每局的统计只来自日期更早的比赛（按 OE 日期字符串比较）。同一天的其他比赛，包括同一系列赛的前几局，都不进入统计。
- **系列赛信息单独处理**：前几局的 pick 通过 Fearless 规则从候选中移除，前几局的 ban 作为系列赛特征。
- **视为 BP 时已知**：双方首发及位置、赛事补丁、规则、当前已进行的选禁。
- **不使用**：本局英雄的最终分路、本局结果和赛后数据。
- **时间加权**：所有计数按 60 天半衰期加权；补丁样本少时向近期全局比率收缩，队伍向补丁热度收缩，选手向位置热度收缩。没见过不等于概率为零。
- **排除争议局**：Leaguepedia 与 OE 最终阵容不一致，或两源顺序在同队连选之外不一致的比赛，不进入训练和评估。
- **数据范围**：2023–2024 年只作为统计历史（如选手英雄池），训练和评估只用 2025 年起的 Fearless 时代。

## 模型

每个阶段（第一轮禁用、第一轮选择、第二轮禁用、第二轮选择）一组权重，在合法候选上做条件 logit，所以同一手的概率之和为 1。合法候选由第一阶段的状态机给出：去掉本局已用、Fearless 已消耗（ban 已消耗英雄虽合法但无效，也去掉）和赛事禁用的英雄。

| 特征 | 含义 |
| --- | --- |
| `meta_pick` / `meta_ban` | 本补丁此前比赛中该英雄的 pick 率 / ban 率 |
| `team_pick` / `team_ban` | 行动方近期选 / 禁该英雄的比例 |
| `opp_pick` | 对手近期选该英雄的比例 |
| `banned_vs_opp` / `banned_vs_self` | 各队对阵对手 / 行动方时禁掉该英雄的比例，即“被针对”的英雄 |
| `role_meta_self` / `role_meta_opp` | 行动方 / 对手还空着的位置上，该英雄的本补丁选用占比 |
| `player_pool_self` / `player_pool_opp` | 行动方 / 对手空缺位置上选手的近期英雄池 |
| `series_ban_self` / `series_banned_vs_self` | 本系列赛前几局行动方禁过 / 对手针对行动方禁过 |

空缺位置按已选英雄的历史分路分布计算所有可能的分配，摇摆英雄会保留几种位置可能，不提前认定最终分路。

训练用 2025-01-01 至 2026-03-31 的 1,795 局、35,893 手（跳过 6 次空 ban 和 1 次实际选择不在合法候选中的记录），在标准化特征上做带 L2 的牛顿法，权重换回原始尺度写入 `models/next_action/v1.json`。

单个权重可以帮助理解，但特征之间相关，不宜孤立解读。例如第二轮禁用的最大权重是 `role_meta_opp`（0.97）和 `player_pool_opp`（0.52）；第一轮禁用中 `meta_pick` 为负，是在已经计入 `meta_ban` 之后的条件效应。

界面上每个候选的“依据”取该英雄贡献最大的几项特征（相对所有候选的平均值），配上对应的比率和样本；“约”表示收缩后的估计值。

## 评估口径

- **时间切分**（`models/next_action/settings.json`）：训练集 2025-01-01 至 2026-03-31，验证集 2026-04-01 至 2026-07-31，测试集 2026-08-01 之后。按系列赛首局日期划分，同一系列赛不跨集合。
- **同队连选按组计分**：第 8–9、10–11、18–19 步来源不保证组内先后，所以预测这组的第一手时，猜中两手中任一手都算命中，概率取两者之和；第二手照常计分。训练仍按记录顺序。
- **Top-K 的含义**：衡量的是对职业队伍实际选择的拟合程度，不证明推荐好坏。

## 版本与修改流程

一个版本就是 `models/next_action/` 下的一个 JSON 文件，包含说明、统计设置（半衰期、收缩强度）、特征列表、拟合设置和各阶段权重。每次预测和每条反馈都记录版本名和文件 sha256。

```sh
cp models/next_action/v1.json models/next_action/v2.json   # 改 version、description、特征或统计设置；weights 与 training 置为 null
python3 scripts/train_next_action.py v2                     # 训练集上拟合，需要 numpy（requirements/model.txt）
python3 scripts/evaluate_next_action.py                     # 验证集：所有可用版本对比，加反馈回归
python3 scripts/evaluate_next_action.py --split test v2     # 只在最终确认时用保留测试集
```

- 已有权重的版本视为冻结：训练脚本拒绝覆盖，需要 `--force`。要改就复制成新版本，旧版本保留，可以随时切回或对比。
- 基线 `baseline-meta`、`baseline-player` 是固定权重版本，不需要训练。
- 应用默认版本由 `settings.json` 的 `default` 决定，界面上也可以切换。
- 训练与报告都是确定性的：同一输入重训得到逐字节相同的文件，报告不含时间戳，并记录输入文件哈希。
- 评估只需要标准库，在 `.venv` 中约 7 秒；训练约 20 秒。
- 本机 `.venv` 暂未装 numpy，因为 2026-10-29 本会话中 PyPI 访问失败（TLS 握手 EOF）。这次训练用的是 Anaconda 自带的 numpy 2.2.6。网络正常后可以 `uv pip install --python .venv/bin/python -r requirements/model.txt`。

## 反馈与回归检查

在预测面板里：

- 某个候选旁点 **标记** → “排太高了”。默认期望它掉出前 5；如果当前已在 5 名之后，默认期望比现在更靠后。
- **漏掉了某个英雄？** → “应该更靠前”。默认期望进入前 5；如果当前已在前 5，默认期望至少前进一名。
- **整体有问题？** → “其他问题”，只记录、人工复查。

期望名次可以手动改，建议写一句原因。每条记录完整保存当时的局面（比赛、Fearless 设置、此前全部动作）、所用版本与文件哈希、当时的前 10 名和期望，存在 `data/feedback/next_action.jsonl`。这个文件纳入 Git，案例会跟着仓库走；如果只想留在本地，把它加入 `.gitignore` 即可。

“反馈记录”面板和评估脚本都会用选定版本重新检查每一条，结论有六种：

| 结论 | 含义 |
| --- | --- |
| 达标 | 满足期望名次 |
| 改善但未达标 | 向期望方向移动，但还没到期望名次 |
| 未变 | 名次没有变化 |
| 变差 | 向相反方向移动 |
| 待人工复查 | “其他问题”类，需要人工看 |
| 无法复现 | 数据变化后这个局面不再合法 |

如果记录后同名版本的文件被改过，会另外标出“模型文件已改动”。

## 已知限制

- 还没有对位、配合、克制关系（P3）、补丁变更知识和韩服排位信号（P5）。v1 只学习“谁常用、谁常被禁、哪个位置还空着”。
- 英雄目录统一为 16.20.1，旧比赛的候选里会有当时尚未上线的英雄；它们没有统计，排名靠后。
- 选手和队伍按 OE 的 player_id / team_id 识别，转会和改名只通过时间加权体现。
- 权重用 2025-01 至 2026-03 拟合，这段时期的比赛对权重来说属于样本内；特征仍然只用此前日期。
- 日期没有时区，“此前日期”按 OE 日期字符串判断。
